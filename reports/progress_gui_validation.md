## 결과

Fourier/Wave 계산에 **단계 진행률, 경과 시간, 이전 동일 설정 기반 예상 남은 시간**을 추가했다.
오른쪽 패널을 계산 설정/계산 실행/결과 보기 카드로 정리하고, 왼쪽 요소 추가를 2열로 배치했다.
1D 단면과 긴 q/ABCD/광파워는 필요할 때 펼쳐 볼 수 있다.

최종 전체 검사: **104 passed / 0 failed / 0 error / 0 skipped**.
기존 광학 계산, 수동 실행/취소, 레이저 귀환광 종단 및 독립 Matplotlib figure를 유지했다.
Linux 실행 파일의 진행 완료와 figure 열기·실제 휠 확대·Pan 드래그도 확인했다.

## 1. 사용자에게 표시하는 진행 상태

- **로딩바:** 입력 준비 → 광학 전파 → 진단/강도·위상 프로파일 → 결과 표시 단계에 따라 갱신.
- **경과 시간:** 실제 wall clock을 약 60 ms 간격으로 갱신. 다른 요소를 선택해도 상단 배지에서 확인.
- **예상 남은 시간:** 이전에 완전히 동일한 요청으로 성공한 기록이 있을 때만 표시.
- **첫 실행:** 가상의 예상 시간을 만들지 않고 경과 시간과 현재 단계를 표시.
- **오래 걸리는 경우:** 이전 시간보다 오래 걸리고 있다는 문구로 전환하며 음수 ETA를 표시하지 않음.
- **취소/실패:** 별도 상태로 표시하고 100% 완료로 처리하지 않음.
- **완료:** worker 결과를 UI에서 받아 처리할 때만 100%로 전환.

퍼센트는 **단계 진행률**이며 전체 FLOP 수나 시간의 비율이 아니다.
전파 callback은 완료한 경로 단계와 검출 계산을 센다. GUI는 전파와 프로파일 준비 구간에
고정된 단계 범위를 배정한다. 큰 FFT 한 번의 내부 진행률은 알 수 없으므로 해당 호출 중에는
bar가 잠시 멈출 수 있으나 경과 시간은 계속 갱신된다. 완료 전에는 최대 99%까지만 표시한다.

시간 추정은 진행률을 시간으로 환산하지 않는다. 장면 fingerprint, 측정면/source/branch/path,
Grid/FOV 및 전파 방식이 같은 마지막 성공 기록을 사용한다. 세션에서 최대 20개를 보관하며
프로그램을 재시작하면 초기화된다. 다른 설정이나 실패/취소 결과를 시간 추정에 재사용하지 않는다.

## 2. 실제 ASM 계산 화면과 시간 관측

720 nm SLM 예제의 Fourier 면, ASM, N=2048, 입력 FOV=6 mm로 실제 계산을 두 번 수행했다.
강제로 기다리게 하거나 가짜 진행률을 주입하지 않은 화면이다.

| 항목 | 관측값 |
|---|---:|
| 첫 계산 경과 시간 | 2.7857 s |
| 두 번째 계산 경과 시간 | 2.6752 s |
| 캡처 시 단계 진행률 | 45% |
| 캡처 시 실제 경과 시간 | 1.9190 s |

## 3. GUI 정리

- 파란색 기본 실행 버튼, 공통 간격·색상·폰트와 상태별 안내 색상을 적용했다.
- 분석 패널을 **01 계산 설정 / 02 계산 실행 / 03 결과 보기**로 묶었다.
- Grid/FOV, 전파 방식, 경로 선택을 한 설정 카드에 배치했다.
- 계산 버튼/취소/로딩바/시간을 한 실행 카드에서 확인할 수 있다.
- 왼쪽의 9개 요소 추가 버튼은 2열로 배치해 구성 요소 목록의 공간을 확보했다.
- 메인 탭 이름을 **요소 설정 / 빔 분석**으로 정리했다.
- 1D 단면과 상세 수치는 기본 접힘이며 선택하면 기존 내용 전체를 볼 수 있다.
- 1366×768에서 계산 버튼과 진행바가 화면 안에 보이는지 검사했다.
- 상단 상태 배지는 다른 탭에서도 보이며 클릭하면 분석 탭으로 돌아간다.

원래 보드/부품 배치와 드래그, q 경로, 물리 파라미터 편집 기능은 유지했다.
독립 2D figure의 원본 해상도·좌표·강도/위상·색상·저장 기능도 그대로 사용한다.
진행 상태 갱신이나 패널 펼치기는 FFT를 재실행하지 않는다.
계산 도중에도 이전 결과를 보존하고, 설정이 바뀌면 기존의 재계산 필요 표시를 유지한다.

## 5. 구현 및 검증 과정

`wave_progress.py`에 Tk와 분리된 진행/시간 상태 모델을 추가했다.
`wave_optics.py`와 `fresnel_optics.py`에는 선택적인 progress callback만 추가했다.
worker는 queue에 진행 메시지를 넣고, Tk 주 스레드만 위젯을 갱신한다.
기존 snapshot, 중복 작업 차단, 취소와 창 닫기 동작을 유지했다.
취소는 현재 NumPy 연산이 끝난 뒤 반영되며 실행 중인 FFT를 강제로 종료하지 않는다.

`app.py`의 UI 구성을 정리하고, worker 메시지를 진행/결과로 구분했다.
기존 수동 계산 테스트의 worker mock은 새 선택 callback을 받을 수 있도록 조정했다.
상세 수치가 접힌 새 UI에서는 펼친 뒤 스크롤 기능을 검증하도록 수정했다.
자동화된 전체 회귀 실행은 104개 모두 통과했다.

실행 파일 검증에서는 작은 폰트의 `2D phase`를 OCR이 `20 phase`로 읽는 문제가 있었다.
D/0의 인식 차이를 보정한 뒤 실제 입력 이벤트로 phase 보기와 독립 figure를 재확인했다.
프로그램 동작이나 광학 오차 허용값을 변경해 통과시킨 것은 아니다.

## 6. 빌드와 남은 범위

Linux x86_64, Python 3.13.5, Tk 8.6, NumPy 2.5.4, Pillow 12.3,
Matplotlib 3.11.2, PyInstaller 6.22.3에서 검증했다. 새 의존성은 추가하지 않았다.
실행 파일: `/workspace/scratch/optic-wave-dist/OpticalBench`.
[빌드 검증·checksum](build_validation.json)과 [빌드 로그](build_linux.log)를 함께 저장했다.
Windows EXE 빌드/실행과 실제 광학 실험은 수행하지 않았다.

남은 범위는 FFT 내부의 세부 진행률, 서로 다른 설정으로의 성능 추정 일반화,
재시작 간 timing history 보존이다. 현재 ETA는 같은 설정에서도 CPU 부하 등으로 달라질 수 있어
항상 근사값으로 표시한다. 기존 ASM/Fresnel의 광학적 가정과 제한은 그대로다.
